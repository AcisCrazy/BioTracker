Base de Datos

FORTNITE NoSQL

¿Cómo gestiona Epic Games millones de jugadores, inventarios y partidas en tiempo real?

El Desafío del Battle Royale

Escalabilidad Masiva

Millones de jugadores concurrentes escribiendo datos (posición, disparos, loot) al mismo tiempo.

Baja Latencia

Nadie quiere lag al construir o disparar. Las lecturas/escrituras deben ser milisegundos.

Esquema Flexible

Cada temporada trae nuevas armas, skins y misiones. SQL rígido rompería el juego.

¿Por qué NO SQL?

La batalla de arquitecturas

VS

SQL Tradicional

(MySQL, PostgreSQL)

  • Esquema Rígido ¿Quieres agregar una nueva stat de "pesca"? Tienes que migrar una tabla con 300 millones de filas. Eso significa downtime.
  • Escalado Vertical Para aguantar más usuarios, necesitas un servidor más grande y caro (CPU/RAM limitada).
  • Joins Lentos Unir tablas de Inventario + Stats + Amigos en tiempo real para 100 jugadores es demasiado lento.

NoSQL Moderno

(DynamoDB, MongoDB, Redis)

  • Schema-less (Flexible) Guarda los datos como JSON. ¿Nueva temporada? Solo agrega el campo nuevo al JSON y listo. Sin migraciones.
  • Escalado Horizontal ¿Llegaron 10 millones de jugadores más? Solo agrega más servidores baratos al clúster. Escalabilidad infinita.
  • Alta Disponibilidad Diseñado para estar siempre activo (AP en el teorema CAP). Si un nodo cae, el juego sigue.

Base de Datos Documental (MongoDB)

Perfil del Jugador

Para guardar la información del usuario, usamos una BD orientada a documentos como MongoDB.

  • Flexible: Podemos agregar nuevos campos como "prestigio" sin migrar toda la base de datos.
  • JSON Nativo: Los datos se guardan igual que los objetos en el código del juego.
Base de Datos Clave-Valor (Redis / DynamoDB)

El Locker (Inventario)

Cuando abres tu inventario en plena partida, necesitas velocidad extrema. Aquí usamos Redis o DynamoDB.

Acceso O(1)

No buscamos en tablas complejas. Solo pedimos: "Dame el inventario de User_ID_123" y la respuesta es instantánea.

KEY: inv_skin_01

VALUE: { "id": "galaxy", "rarity": "legendary" }

KEY: inv_pick_05

VALUE: { "id": "balloon_axe", "rarity": "epic" }

> GET inventory:user:Ninja_01
< "skin_galaxy", "pickaxe_reaper", "glider_umbrella"...
Base de Datos de Grafos (Neo4j)

Amigos y Squads

Para saber "¿Quién es amigo de quién?" o "¿Quién jugó con quién ayer?", las tablas son lentas. Los grafos son perfectos para relaciones.
